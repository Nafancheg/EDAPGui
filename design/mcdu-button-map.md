# MCDU Button Map — инженерная спецификация раскладки

> Выдача по ТЗ `design/mcdu-avionics-prompt.md`. Роль: инженер HMI / эргономика авионики.
> Приоритет требований: **1) эргономика/безопасность → 2) конвенция MCDU → 3) внешний вид**.
> Документ = три этапа (ИА → структура страниц → раскладка слотов) + план декомпозиции
> INIT/DIR + обоснования + приоритет реализации. Кода нет — только спецификация.

Обозначения: **[A]** действие, **[T]** тумблер, **[V]** индикация, **[E]** редактируемое
значение (scratchpad → LSK), **[план/бэкенд]** — функция ещё не реализована, слот закладывается.

# ЭТАП 1 — Информационная архитектура

## 1.1 Легенда 12 функциональных клавиш

| Клавиша | Статус | Страница | Назначение (1 строка) |
|---|---|---|---|
| **DIR** | активна | DIRECT-TO | прыжок напрямую, минуя план: ближайшая scoopable / ближайшая система / ввод системы [план/бэкенд] |
| **PROG** | активна, **boot default**, LED 🟢/⚫ | FLIGHT (фазовая) | исполнение полёта по фазам DEPART→CLIMB→CRUISE→APPROACH→ARRIVAL→LND; прогресс трипа |
| **PERF** | активна | RPY CURVES | редактор кривых Roll/Pitch/Yaw + Auto-tune + сохранение |
| **INIT** | активна | PREFLIGHT | преполётная подготовка / «дом»: подтверждение маршрута, корабль, вход во все разделы |
| **DATA** | активна | SYSTEM DATA | справочные данные: текущая система, сканы, EDSM-инфо [частично план] |
| **F-PLN** | активна | ACTIVE ROUTE | активный маршрут (NavRoute.json): список систем, DEST/jumps, Fast Travel |
| **RAD NAV** | **INOP** | — | прямого аналога в ED нет (зафиксировано ТЗ) |
| **FUEL PRED** | активна, LED 🟢/🟡/🔴/⚫ | FUEL PRED | прогноз топлива (jumps until refuel и др.) + управление заправкой |
| **SEC F-PLN** | активна | SECONDARY ROUTE | резервный маршрут: fuel-safe / fast-risky, COMPARE, ACTIVATE [план/бэкенд] |
| **ATC COMM** | **INOP** | — | резерв под будущие станционные comms (зафиксировано ТЗ) |
| **MCDU MENU** | активна | SETTINGS | корень пилотских настроек; подстраницы OPTIONS / CONFIG / MAINT(⚙dev) |
| **AUTO TUNE** | **INOP** | — | Auto-tune RPY живёт на PERF; клавишу не занимаем (зафиксировано ТЗ) |

Annunciator LED — строго по Style Guide, только две клавиши:
- **FUEL PRED**: 🟢 NORMAL · 🟡 WARNING · 🔴 CRITICAL · ⚫ данных нет (unknown ≠ авария).
- **PROG**: 🟢 ассист активен (FSD или SC engaged) · ⚫ ассистов нет. Без мигания.

Вне сетки: **STOP ALL** — отдельная выделенная красная кнопка с guard-бортиком,
пространственно отделена от LSK и slew/NEXT, всегда видима, действует одинаково на всех
страницах и во всех фазах (`assist.stop_all`). Ни один слот LSK её не дублирует.

**AIRPORT** — INOP (резерв «ближайшая станция/порт», сейчас не назначена).

## 1.2 Дерево навигации (макс. глубина 2 уровня)

```
BOOT ──► PROG · FLIGHT (фазовая страница, уровень 1)
          фазы (не подстраницы — состояния одной страницы, slew ←/→):
          DEPART ↔ CLIMB ↔ CRUISE ↔ APPROACH ↔ ARRIVAL ↔ LND ↺ DEPART

INIT      PREFLIGHT (ур.1) ── R6 PROG> (к полёту)
F-PLN     ACTIVE ROUTE (ур.1, многостраничный список — slew ←/→, тот же уровень)
SEC F-PLN SECONDARY ROUTE (ур.1) ── страницы списка SEC-маршрута (slew, тот же уровень) [план]
DIR       DIRECT-TO (ур.1) [план]
FUEL PRED FUEL PRED (ур.1) ──► REFUEL SELECT (ур.2, L1; возврат L6)
PERF      RPY CURVES (ур.1)
DATA      SYSTEM DATA (ур.1, доп. страницы данных — slew) [частично план]
MCDU MENU SETTINGS (ур.1) ──► OPTIONS (ур.2) / CONFIG (ур.2) / MAINT ⚙dev (ур.2)
```

**Досягаемость частых функций от boot (PROG):**

| Функция | Нажатий от boot |
|---|---|
| FSD Route Assist (главный тумблер) | **0** — PROG открыт, активная фаза автоподсвечена, L1 в CRUISE |
| Прогресс трипа (jumps/ETA/LY) | **0** — правая колонка CRUISE |
| STOP ALL | **0** — отдельная красная кнопка |
| Здоровье топлива | **0** — LED на клавише FUEL PRED; детали = 1 (клавиша) |
| Маршрут (список) | 1 — клавиша F-PLN |
| SC Assist / стыковка / throttle | 1 — slew → к своей фазе (или 0, если фаза уже активна) |
| Запуск заправки | 2 — FUEL PRED → L1 ACTIVATE REFUEL |
| Настройки / dev | 1–2 — MCDU MENU → подстраница |

## 1.3 Постоянные элементы всех страниц (контракт)

- **Header, ровно 2 ряда, без нажимаемых элементов:**
  1. титул страницы слева; справа индикатор контекста — `N/M →` для многостраничных,
     имя активной/просматриваемой фазы для PROG;
  2. ряд состояния: слева `AP: <ap_state>`, справа `MODE <ap_mode>`.
  При отсутствии соединения — индикатор `OFFLINE` в шапке.
- **Footer = scratchpad** (charset `A–Z 0–9 . / + - ␠`, ≤22 симв.; CLR/ESC; ошибки
  `INVALID` / `NOT ALLOWED` / `NOT CONNECTED` показываются ~1.5 с, ввод сохраняется).
- **R6 = NEXT PAGE / NEXT PHASE>** (только листание; пусто, если листать нечего).
- **L6 = <RETURN** на подстраницах; на корневых страницах L6 **пуст** (зарезервирован).
- Лево = действия [A]/[T]; право = параметры/состояние [V]/[E]. Строки 1–2 — самое частое.
- Пустые слоты — пустые (не INOP-заглушки). Нет значения → `---` приглушённо.
- Пустая по смыслу страница → центрированная подсказка (`NO ACTIVE ROUTE` и т.п.).
- Одинаковая функция = один и тот же слот на всех страницах, где встречается
  (закреплено ниже: ALIGN TGT = L2; THR 0/50/100 = L3/L4/L5; THROTTLE-значение = R1;
  SHIP = R2; TARGET = R3; SAVE ALL = L5).

# ЭТАП 2 — Структура страниц

## 2.1 PROG · FLIGHT — фазовая страница (boot default)

**Назначение:** исполнение полёта. Одна страница, шесть фаз-состояний. Slew ←/→ листает
фазы; **активная фаза автоподсвечивается** по ship_status/ap_mode (при boot открывается
именно она); slew ↓ мгновенно возвращает к активной фазе, если пилот улистал в сторону.
R6 всегда `NEXT PHASE>`. Индикатор шапки = имя просматриваемой фазы (приглушённо, если
просматриваемая ≠ активная). Глубина: 1 уровень, подстраниц нет.

| Фаза | Левая колонка (действия) | Правая колонка (параметры) |
|---|---|---|
| **DEPART** | Undock/Launch; пресеты тяги 0/50/100 | throttle-значение; статус корабля; первая цель; подтверждение маршрута (DEST + jumps) |
| **CLIMB** | выход в суперкруиз; align to target; пресеты тяги | throttle; статус корабля; цель |
| **CRUISE** | **FSD Route Assist** (гл. тумблер); FSS scan; honk; ELW scanner; скуп on-demand | jumps n/m; ETA; следующая цель; пройдено/осталось; топливо % + scoopable |
| **APPROACH** | **SC Assist**; align to target | дистанция до дропа [план]; статус корабля; цель |
| **ARRIVAL** | request docking; dock/land; refuel·repair [план] | статус корабля; цель (станция/тело); ветка: индикатор `ARRIVAL·STN` / `ARRIVAL·PLT` |
| **LND** [план/бэкенд] | drop to OC; glide; surface approach; target POI; final descent | ALT; своя позиция lat/lon; HDG/пеленг; дистанция до цели; **ввод координат цели [E]** |

Переходы NEXT PHASE>: DEPART→CLIMB→CRUISE→APPROACH→ARRIVAL→ (цель-станция: →DEPART,
петля нового плеча; цель-планета: →LND) →DEPART. STOP ALL — hardware-кнопка, не в сетке.

## 2.2 INIT · PREFLIGHT — «дом» преполёта

**Назначение:** подтвердить активный маршрут, увидеть корабль/топливо/связь, войти в любой
раздел. Лево — переходы в разделы (F-PLN, FUEL PRED, PERF, DATA, SETTINGS); право — сводка
(DEST, jumps, корабль, топливо, соединение). R6 = `PROG>` — «к полёту» (конвенция Airbus:
INIT → следующая страница потока подготовки). Глубина 1, подстраниц нет.

## 2.3 F-PLN · ACTIVE ROUTE

**Назначение:** активный план (NavRoute.json). Строки 1–4 — список систем (4 на страницу,
листание slew ←/→ и R6 NEXT PAGE>, индикатор `ROUTE n/m →`); строка 5 фиксирована на всех
страницах списка: слева Fast Travel [T], справа DEST + total jumps [V]. Нажатие левого LSK
строки списка → per-system info (класс/scoopable/дистанция) сообщением в scratchpad — без
подстраницы. Обновление списка автоматическое (при открытии страницы и при смене
location); отдельная кнопка REFRESH упразднена (не в инвентаре — см. Замечания).
Пустое состояние: `NO ACTIVE ROUTE` / `PLOT ROUTE IN GALAXY MAP` по центру. Глубина 1.

## 2.4 SEC F-PLN · SECONDARY ROUTE [план/бэкенд]

**Назначение:** резервный план «в кармане». Лево — действия: PLOT FUEL-SAFE, PLOT
FAST/RISKY, ACTIVATE SEC (свап primary⇄secondary — двухшаговое подтверждение). Право —
цель SEC [E] и COMPARE-сводка primary vs secondary (jumps / LY / заправки / риск).
R6 NEXT PAGE> — страницы списка SEC-маршрута (формат как F-PLN). Глубина 1 (список — slew).

## 2.5 DIR · DIRECT-TO [план/бэкенд]

**Назначение:** лететь напрямую, минуя план. Лево — NEAREST SCOOPABLE, NEAREST SYSTEM.
Право — ввод системы [E] и карточка выбранной цели (имя/класс/LY). Глубина 1.

## 2.6 FUEL PRED · топливо

**Назначение:** прогноз и здоровье топлива + запуск заправки. Право (сверху вниз по частоте
взгляда): топливо на борту (%+тонны), **jumps until refuel** (ключевой показатель), средний
расход, range forecast, порог дозаправки [E]. Лево: L1 ACTIVATE REFUEL → подстраница
REFUEL SELECT (уровень 2). Fuel status (NORMAL/WARNING/CRITICAL) питает LED клавиши и
дублируется индикатором в шапке страницы. Нет данных → `---`, LED ⚫, статус не CRITICAL.

**REFUEL SELECT (ур.2):** лево — источники: звезда этой системы (существующий скуп
on-demand), ближайшая станция [план], ближайшая точка заправки [план]; право — карточки
источников (класс звезды + scoopable и т.д.). L6 <RETURN.

## 2.7 PERF · RPY CURVES (существует — приводится к контракту)

**Назначение:** кривые Roll/Pitch/Yaw. Лево — действия: выбор оси (цикл), Auto-tune [T],
SAVE SHIP, SAVE ALL. Право — контекст и значения: throttle [E], speed-контекст, выбранная
точка, значение точки [E]. Выбор точки — slew ←/→ (внутристраничный выбор — законная роль
slew), drag-график под прибором сохраняется. Глубина 1.

## 2.8 DATA · SYSTEM DATA

**Назначение:** справка (readout) о текущей системе: система, звезда, сканы, EDSM-инфо
[план]. Лево — единственное действие: запрос EDSM [план]. Доп. страницы данных — slew/R6.
Глубина 1.

## 2.9 MCDU MENU · SETTINGS

**Назначение:** корень настроек «настроил и забыл». Лево: входы в OPTIONS (пилотские
тумблеры), CONFIG (бинды/настройки игры), MAINT ⚙dev (спрятан на ур.2 — пилот в полёте не
натыкается), плюс LOAD ALL / SAVE ALL. Право — статус соединения ядра/игры [V].

- **OPTIONS (ур.2):** Voice, Overlay, Hotkeys, Randomness, Automatic logout — [T]. L6 RETURN.
- **CONFIG (ур.2):** Activate-Elite-each-key [T], Reload bindings, Auto-assign keys,
  Refresh game settings — [A]; справа статус биндов [V]. L6 RETURN.
- **MAINT ⚙dev (ур.2):** CV View, Debug Overlay/OCR/Images — [T]; тайминги ModDelay /
  DefHoldTime / RepeatDelay — [E] справа. L6 RETURN.

# ЭТАП 3 — Раскладка органов управления по слотам

Общее для всех таблиц: header/footer по контракту; STOP ALL — hardware вне сетки; пустые
слоты в таблицах опущены (остаются пустыми); `OFFLINE` блокирует все [A]/[T]/[E] с
сообщением `NOT CONNECTED`.

## 3.1 PROG — фазы

### DEPART (авто-выбор: пристыкован/на поверхности)
| Слот | Метка | Тип | Что делает |
|---|---|---|---|
| L1 | `<UNDOCK` / `<LAUNCH` (по контексту dock/landed) | A | отстыковка / взлёт |
| L3 | `<THR 0` | A | throttle.set 0 |
| L4 | `<THR 50` | A | throttle.set 50 |
| L5 | `<THR 100` | A | throttle.set 100 |
| R1 | `THROTTLE  nn%` | E | значение тяги; scratchpad: целое 0–100, иначе `INVALID` |
| R2 | `SHIP  <ship_status>` | V | состояние корабля |
| R3 | `TARGET  <target>` | V | первая цель маршрута |
| R4 | `ROUTE  <dest> · N JMP` | V | подтверждение активного маршрута; нет маршрута → `---` |
| R6 | `NEXT PHASE>` | A | → CLIMB |

### CLIMB
| Слот | Метка | Тип | Что делает |
|---|---|---|---|
| L1 | `<ENTER SC` | A | выход в суперкруиз (команды в транспорте пока нет — добавить, см. Замечания) |
| L2 | `<ALIGN TGT` | A | разово довернуть нос на цель |
| L3 | `<THR 0` | A | как в DEPART (слот закреплён) |
| L4 | `<THR 50` | A | — |
| L5 | `<THR 100` | A | — |
| R1 | `THROTTLE  nn%` | E | как в DEPART (слот закреплён) |
| R2 | `SHIP  <ship_status>` | V | — |
| R3 | `TARGET  <target>` | V | цель первого прыжка |
| R6 | `NEXT PHASE>` | A | → CRUISE |

### CRUISE (самая частая фаза)
| Слот | Метка | Тип | Что делает |
|---|---|---|---|
| L1 | `<FSD ROUTE  ON/OFF` | T | **главный автопилот** — assist.start/stop(fsd); верхний левый слот, 0 нажатий от boot |
| L2 | `<FSS SCAN` | A | полное сканирование системы (на остановке у звезды) |
| L3 | `<HONK` | A | D-scanner honk (авто-honk на прибытии — поведение FSD-ассиста) |
| L4 | `<ELW SCAN  ON/OFF` | T | детектор Earth-like при прыжках |
| L5 | `<SCOOP NOW` | A | скуп on-demand у звезды этой системы — та же команда ядра, что STAR THIS SYSTEM на REFUEL SELECT (см. Замечание 10) |
| R1 | `JUMPS  n/m` | V | jump_cnt / total_jumps |
| R2 | `ETA  hh:mm` | V | расчётное время прибытия |
| R3 | `TARGET  <next system>` | V | следующий прыжок |
| R4 | `DIST  x LY · N LEFT` | V | total_dist_jumped + jumps_remaining |
| R5 | `FUEL  nn.n% · SCOOP/✗` | V | топливо + scoopable текущей звезды (пара к L5); цветовые пороги <10% alert / <25% warn; заправка видна и в `AP:` шапки |
| R6 | `NEXT PHASE>` | A | → APPROACH |

### APPROACH
| Слот | Метка | Тип | Что делает |
|---|---|---|---|
| L1 | `<SC ASSIST  ON/OFF` | T | assist.start/stop(sc); в другой фазе от FSD — несовместимые режимы разнесены |
| L2 | `<ALIGN TGT` | A | слот закреплён (как CLIMB) |
| R1 | `DIST TO DROP  ---` | V [план] | дистанция до дропа; источника данных пока нет → `---` |
| R2 | `SHIP  <ship_status>` | V | — |
| R3 | `TARGET  <target>` | V | станция/сигнал назначения |
| R6 | `NEXT PHASE>` | A | → ARRIVAL |

### ARRIVAL (ветвится; индикатор шапки `ARRIVAL·STN` / `ARRIVAL·PLT`)
| Слот | Метка | Тип | Что делает |
|---|---|---|---|
| L1 | `<REQ DOCKING` | A | запрос стыковки |
| L2 | `<DOCK / LAND` | A | стыковка / посадка на площадку |
| L3 | `<REFUEL·REPAIR` | A [план] | станционные услуги после стыковки |
| R2 | `SHIP  <ship_status>` | V | — |
| R3 | `TARGET  <станция/тело>` | V | — |
| R6 | `NEXT PHASE>` | A | цель-станция → DEPART (петля нового плеча); цель-планета → **LND** |

### LND — посадка на планету [план/бэкенд]
| Слот | Метка | Тип | Что делает |
|---|---|---|---|
| L1 | `<DROP TO OC` | A [план] | выход из SC в низкую орбиту |
| L2 | `<GLIDE` | A [план] | сход с орбиты / вход в глайд |
| L3 | `<SURFACE APPR` | A [план] | полёт над поверхностью к точке |
| L4 | `<TGT: POI/MARKER` | A [план] | цель по игровой метке (settlement/base) |
| L5 | `<FINAL DESCENT` | A [план] | шасси, вертикальный спуск, касание |
| R1 | `ALT  nnnn` | V | высота (Status.json, читается уже сейчас) |
| R2 | `POS  lat/lon` | V | своя позиция (Status.json) |
| R3 | `HDG nnn · BRG nnn` | V | свой курс и пеленг на цель |
| R4 | `DIST TO TGT  n.n KM` | V | по своей позиции + PlanetRadius |
| R5 | `TGT COORDS  ----/----` | **E** | ввод `ШИРОТА/ДОЛГОТА` (напр. `-74.12/05.48`). Валидация LSK: два десятичных числа через `/`, знак и дробная часть опциональны, lat∈[−90,+90], lon∈[−180,+180]; невалидно → `INVALID`, ввод сохраняется; валидно → показать распознанные lat/lon, начать наведение |
| R6 | `NEXT PHASE>` | A | → DEPART (новый цикл) |

**Slew на PROG:** ←/→ — предыдущая/следующая фаза; ↓ — вернуться к активной фазе; ↑ — INOP.

## 3.2 INIT · PREFLIGHT
| Слот | Метка | Тип | Что делает |
|---|---|---|---|
| L1 | `<F-PLN` | A | переход на ACTIVE ROUTE |
| L2 | `<FUEL PRED` | A | переход на FUEL PRED |
| L3 | `<PERF` | A | переход на RPY CURVES |
| L4 | `<DATA` | A | переход на SYSTEM DATA |
| L5 | `<SETTINGS` | A | переход на MCDU MENU |
| R1 | `DEST  <destination>` | V | подтверждение маршрута; нет → `NO ROUTE` |
| R2 | `JUMPS  N` | V | всего прыжков плана |

# План декомпозиции текущего перегруженного экрана INIT/DIR

Сейчас INIT и DIR открывают один экран, где свалено всё. Куда уходит каждый элемент:

| Элемент текущего INIT | Новое место | Слот |
|---|---|---|
| FSD ROUTE тумблер (L1) | PROG · фаза CRUISE | L1 |
| SUPERCRUISE тумблер (L2) | PROG · фаза APPROACH | L1 |
| THROTTLE (R1, press-цикл + ввод) | PROG · DEPART/CLIMB: значение R1 [E] + пресеты L3–L5 [A] | R1 / L3–L5 |
| FUEL % (R2) | FUEL PRED R1; дубль-взгляд PROG·CRUISE R5; здоровье — LED клавиши | R1 / R5 |
| FAST TRAVEL (L3) | F-PLN (это режим прокладки активного плана) | L5 |
| SHIP status (R3) | PROG R2 (фазы) + INIT R3 (профиль) | R2 / R3 |
| SYSTEM (L4) | DATA R1; контекст звезды — FUEL PRED→REFUEL SELECT R1 | R1 |
| STAR class/scoop (R4) | REFUEL SELECT R1 + DATA R2 | R1 / R2 |
| JUMPS n/m (L5) | PROG · CRUISE | R1 |
| ETA (R5) | PROG · CRUISE | R2 |
| TARGET (L6) | PROG R3 (закреплённый слот во всех фазах) | R3 |
| **STOP ALL (R6 — LSK!)** | **отдельная красная hardware-кнопка вне сетки** | вне сетки |
| Клавиша DIR (сейчас = INIT) | собственная страница DIRECT-TO [план/бэкенд] | §3.5 |
| Клавиша INIT | новая страница PREFLIGHT (§3.2): подтверждение маршрута + входы в разделы | §3.2 |

# Приведение существующих страниц к контракту (нарушения → исправления)

1. **INIT: STOP ALL на LSK R6** — двойное нарушение: аварийная функция на софт-клавише
   рядом с местом NEXT (принцип 4, приоритет 1) и занят зарезервированный R6.
   → Вынести в отдельную красную кнопку вне сетки (уже в контракте).
2. **INIT: действия справа** (THROTTLE press-цикл R1, STOP ALL R6) — нарушение
   «лево=действия». → Пресеты тяги уходят влево (L3–L5), справа остаётся значение [E].
3. **F-PLN: `REFRESH>` в слоте R6** (пустое состояние) — R6 зарезервирован под NEXT PAGE,
   и action размещён справа. → Кнопка упразднена, обновление автоматическое (см. Замечания).
4. **F-PLN: правый LSK строки списка нажимаем** (дублирует info-действие) — справа только
   параметры. → Нажимаем только левый LSK строки; правые ячейки списка — [V].
5. **PERF: `>NEXT PT` на R3, `SAVE>` на R4 справа** — действия справа. → Выбор точки —
   slew ←/→; SAVE уходит влево (L4 SAVE SHIP, L5 SAVE ALL).
6. **PERF: `SAVE ALL SETTINGS>` в строке 6 (зона L6)** — L6 зарезервирован под RETURN.
   → SAVE ALL на L5 (слот закреплён и на MCDU MENU).
7. **PERF: THROTTLE R1 press-цикл** — скрытое действие справа. → R1 остаётся [E]
   (scratchpad-ввод), цикл по нажатию убрать.
8. **FUEL: dev-сообщение «AWAITS FUELSTATE (PHASE 3)» на пилотской странице** — служебный
   текст. → По контракту «нет данных»: `---` + LED ⚫.
9. **DIR ведёт на экран INIT** — переопределение конвенционного смысла клавиши.
   → DIR = DIRECT-TO (§3.5), до реализации бэкенда — страница с [план]-разметкой и
   подсказкой (не «PAGE INOP», т.к. клавиша по ИА активна).

# Обоснования нетривиальных решений

- **FSD и SC Assist в разных фазах, а не соседними тумблерами** — принцип 3 (несовместимые
  режимы разделять), приоритет 1: пилот физически не видит оба тумблера одновременно,
  ошибочное включение «не того ассиста» исключено композицией экрана.
- **Пресеты THR 0/50/100 как три отдельных LSK, а не один циклический** — приоритет 1:
  цикл требует смотреть на экран и считать нажатия; три фиксированные кнопки дают слепое
  попадание. Слоты L3–L5 закреплены между фазами (мышечная память, контракт).
- **Закреплённые слоты THROTTLE=R1, SHIP=R2, TARGET=R3, ALIGN TGT=L2, SAVE ALL=L5** —
  пункт контракта «одинаковые функции не меняют позицию».
- **Jumps until refuel на R2 (вторая строка) FUEL PRED** — «частота взгляда → заметность»:
  ключевой запрошенный показатель сразу под общим остатком.
- **% и тонны топлива объединены в одну ячейку R1** — 6 readout-значений не помещаются в
  5 слотов (R6 зарезервирован); обе величины — один взгляд «сколько топлива». Приоритет 1
  (не плодить подстраницы) выше эстетики плотной ячейки.
- **CURRENT STAR перенесена на REFUEL SELECT** — звезда важна ровно в момент решения
  «где заправиться»; принцип 1 (одна страница — одна задача).
- **Порог RFL THRESHOLD остался на главной FUEL PRED (R5)** — это параметр поведения
  автопилота, который пилот сверяет с прогнозом (R2–R4) на одном экране.
- **Выбор точки кривой на PERF — slew ←/→** — slew по ТЗ = «навигация/выбор внутри
  страницы»; освобождает два слота и убирает действия с правой стороны (контракт).
- **MCDU MENU трёхвходовый (OPTIONS/CONFIG/MAINT)** — конвенция MCDU MENU как корня меню
  (приоритет 2) + требование спрятать dev глубже (принцип 9); глубина остаётся ≤2.
- **Activate-Elite-each-key отнесена к CONFIG, а не к пилотским OPTIONS** — это параметр
  надёжности ввода «настроил и забыл», не полётный тумблер; заодно OPTIONS помещается в
  5 слотов без второй страницы.
- **INIT R6 = `PROG>`** — конвенция Airbus «INIT → следующая страница потока подготовки»
  (приоритет 2); семантика R6 «NEXT PAGE» не нарушена.
- **ARRIVAL-ветка через индикатор шапки + смысл NEXT PHASE** — ветвление станция/планета
  не плодит страниц: меняется только пункт назначения перехода R6 (принцип «не плоди
  страницы»).
- **Двухшаговое ACTIVATE SEC (`CONFIRM?`)** — свап активного плана в полёте — операция
  с последствиями; подтверждение на том же LSK не добавляет глубины (приоритет 1).

# Приоритет реализации

Порядок по запросу заказчика (исполнение трипа → контроль топлива → маршрут):

1. **PROG (фазовая страница)** — boot default, LED PROG, STOP ALL-кнопка вне сетки;
   первыми фазы CRUISE → APPROACH → DEPART/CLIMB → ARRIVAL (LND — каркас с [план]).
   Одновременно INIT/DIR перестают открывать старый экран (INIT — упрощённый §3.2,
   DIR — [план]-страница).
2. **FUEL PRED + LED** — расчёты avg/jump, jumps-until-refuel, range из журнала;
   подстраница REFUEL SELECT (пункт «звезда этой системы» работает уже сейчас).
3. **F-PLN приведение к контракту** — список 4/страницу, фикс-строка 5 (FAST TRAVEL +
   DEST), R6 NEXT PAGE, автообновление вместо REFRESH.

Далее: INIT (полный), MCDU MENU (OPTIONS/CONFIG/MAINT), PERF-приведение, DATA;
[план/бэкенд]-очередь: DIR, SEC F-PLN, LND (по мере готовности плоттера/навигации).

# Замечания: отклонения и вскрытые структурные проблемы

Правило «фиксируй замечанием, не меняй молча» — все пункты ниже отражены в спецификации
явно, а не втихую:

1. **Кнопка REFRESH (текущий F-PLN) упразднена** — её нет в инвентаре функций ТЗ
   («это всё, что нужно разложить»), обновление сделано автоматическим (открытие страницы
   + смена location). Если заказчику нужен ручной refresh — единственное законное место
   по контракту — левый столбец, ценой строки списка.
2. **SEC DEST [E] добавлен на SEC F-PLN** — инвентарь не содержит поля цели для плоттера,
   но PLOT-действия без цели неисполнимы. Минимальное необходимое дополнение, по
   умолчанию наследует DEST активного плана.
3. **«Выход в суперкруиз» (CLIMB L1) отсутствует в транспорте команд** — в списке
   готового транспорта нет прямой команды enter-SC; функция задана моделью фаз ТЗ.
   Требуется команда бэкенда (или маппинг на существующий ассист).
4. **DIST TO DROP (APPROACH R1) не имеет источника данных** — игра не публикует дистанцию
   в SC без OCR; слот заложен, до появления источника показывает `---` [план].
5. **«Выбор корабля» на INIT сведён к индикации профиля** — профиль корабля определяется
   автоматически из журнала (ship_changed); интерактивный выбор без поддержки ядра невозможен.
   Слот R3 показывает активный профиль; если ядро даст выбор — он станет [A/E] на том же слоте.
6. **INIT частично дублирует функциональные клавиши** (входы в разделы) — осознанная
   избыточность по зафиксированному решению «INIT = дом, вход во все разделы»; полезна для
   обучаемости, но при дефиците места первыми кандидатами на сокращение являются L1–L5 INIT.
7. **6 readout-значений топлива против 5 слотов** — решено объединением %+тонн в одну
   ячейку и переносом CURRENT STAR на REFUEL SELECT (см. Обоснования); альтернатива
   (вторая страница FUEL) отвергнута как лишняя глубина для read-only данных.
8. **ARRIVAL «undock → петля»** — отдельного органа undock в ARRIVAL нет: возврат к
   DEPART (где UNDOCK — L1) выполняется через R6 NEXT PHASE. Петля плеча маршрута
   замыкается навигацией, а не дублированием кнопки.
9. **Индикатор просматриваемой vs активной фазы** — контрактный header отдаёт правый слот
   титульного ряда одному значению; при ручном листании показывается имя просматриваемой
   фазы приглушённым стилем, возврат — slew ↓. Если потребуется одновременно видеть обе —
   нужен пересмотр контракта header (не делалось).
10. **SCOOP NOW (CRUISE L5) дублирует STAR THIS SYSTEM (REFUEL SELECT L1)** — одна и та же
    команда ядра (скуп on-demand) в двух контекстах: быстрое действие в полёте и выбор
    источника заправки. Осознанное отклонение от правила «одинаковая функция = один слот»:
    метки и контексты различаются, а фазовая таблица ТЗ явно относит «скуп топлива» к
    органам CRUISE (частота → досягаемость, принцип 2). Идея взята из выдачи
    MCDU_HMI_Spec при сравнении дизайнов (см. `mcdu-design-comparison.md`).
12. **F-PLN — непрерывная прокрутка вместо страниц (замена §3.3 «4/страницу + NEXT PAGE»)** —
    по решению заказчика (2026-07-11): как на реальном авиационном F-PLN, весь план —
    один список, мотаемый вертикальным slew (↑/↓ по строке, ←/→ на окно=4), без кнопки
    NEXT PAGE (R6 освобождён). Окно показа = 4 строки (rows 1–4), `S.routePage` = индекс
    верхней строки. Внизу добавлена сводка всего плана `TOTAL  N JMP · X.X LY` (row 6,
    [V]) — total LY считается на клиенте суммой `dist_ly`. Фикс-строка 5 (FAST TRAVEL + DEST)
    и «только левый LSK» из §3.3 сохранены. Реализация — `renderROUTE`/`slew` в mcdu.js.
11. **PROG L6 = `<PREV PHASE` (контракт: L6 корня пуст)** — отступление от §1.3/§3.1,
    внесено по решению заказчика (2026-07-11). Обоснование: фазы Elite, в отличие от
    односторонней авиационной последовательности, ходят в обе стороны (петля
    ARRIVAL→DEPART, регресс из SC в манёвр), поэтому PREV/NEXT сделаны симметричными на
    L6/R6. Slew ←/→ по-прежнему дублируют листание, ↓ — прыжок к активной фазе.
    Реализация — в `webserver/static/mcdu.js` (`renderPROG`/`stepPhase`).
