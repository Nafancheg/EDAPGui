## Критерии (из требований ТЗ)

1. **Полнота выдачи** — точные таблицы слотов для каждой страницы и каждой фазы PROG.
2. **Соблюдение визуального контракта** — лево=действия, право=параметры/[E];
   L6=RETURN только на подстраницах; R6=NEXT; пустые слоты пустые; LED только на 2 клавишах.
3. **Покрытие инвентаря функций** — ничего не потеряно, ничего не выдумано.
4. **Принятые решения** — нет «реши сам» и открытых концов.
5. **Разбор существующих страниц** — где текущие INIT/DIR/F-PLN/PERF нарушают контракт.
6. **Честная фиксация проблем ТЗ** — недостающий транспорт команд, источники данных.

## Разбор по дизайнам

### A — DeepSeek: полный, но с контрактными ошибками

**Плюсы**
- Единственный кроме D довёл Этап 3 до таблиц по всем страницам.
- Идея показывать класс текущей звезды прямо в CRUISE (R4 `STAR: G2V`) — полезный
  контекст для скупа, **частично принято** (влито в ячейку топлива R5).
- Приоритеты реализации совпадают с ТЗ.

**Минусы (конкретно)**
1. **LND L6 = `TOUCHDOWN`** — критичное действие посадки в зарезервированном под RETURN
   слоте, вплотную к R6 NEXT PHASE. Прямое нарушение контракта и принципа 4.
2. **MCDU MENU L6 = `MAINT>`** — переход в разделе занимает резерв RETURN; входы в
   подстраницы по контракту живут в левой колонке L1–L5.
3. **FUEL `REFUEL THRESH [E]` на L1** — редактируемое поле слева (контракт: [E] справа),
   и самый доступный слот страницы отдан редко меняемому порогу.
4. **FUEL `L6 RETURN → INIT` на корневой странице** — у корня нет родителя; «возврат туда,
   откуда пришёл» — состояние, которого контракт не предусматривает.
5. **Потери инвентаря:** на FUEL нет Avg fuel/jump и Range forecast; в CLIMB нет органа
   «выход в суперкруиз»; в ARRIVAL нет Refuel·Repair; Load/Save All — «можно опустить».
6. **ARRIVAL не ветвится:** NEXT PHASE всегда → LANDING, петля «станция → DEPART» потеряна.
7. Per-system info — «возможно в scratchpad или в правой части, детали реализации»:
   открытое решение, что ТЗ явно запрещает.

### B — MCDU_HMI_Spec (Stage 1–3): верная ИА, слабая проработка

**Плюсы**
- Корректная информационная архитектура и легенда клавиш.
- **`SCOOP NOW` [A] как орган фазы CRUISE** — единственный, кто заметил «скуп топлива»
  в фазовой таблице ТЗ. **Принято** (CRUISE L5).
- ARRIVAL с явной undock-петлёй — идея верная (в базе решена навигацией NEXT PHASE→DEPART,
  см. замечание 8 базового документа).

**Минусы**
1. **`RETURN` на L6 всех фаз PROG** — PROG корневая и boot-default, возвращаться некуда.
2. **Выдуманные readouts без источника:** CLIMB R1 HEADING / R2 SPEED, APPROACH R2 BEARING /
   R4 SPEED — этой телеметрии нет ни в инвентаре, ни в Status.json вне фазы посадки.
3. APPROACH L3 `Drop [A]` — действия нет в инвентаре (в Этапе 2 это был readout
   «Drop readiness», в Этапе 3 молча стал кнопкой).
4. DEPART L4 `ROUTE CONFIRM [A]` — подтверждение маршрута по ТЗ индикация, не действие.
5. FUEL `Threshold [E]` слева (L2).
6. Этап 3 не доведён: F-PLN «L1–L5 выбор, R1–R5 информация», INIT/DATA/MAINT без слотов.
7. Нет плана декомпозиции INIT/DIR, нет разбора нарушений текущих страниц.

### C — Grok: правильные принципы, выдача-конспект

**Плюсы**
- ИА корректна, все зафиксированные решения ТЗ соблюдены на уровне структуры.
- Явный план декомпозиции INIT/DIR («ничего не остаётся сваленным»).
- Fuel status прямо в CRUISE (R3) — совпадает с R5 базового документа.

**Минусы**
1. **Этап 3 выполнен только для CRUISE**, остальные фазы — «аналогично, кратко», страницы —
   списки без слотов. Это не «спецификация, реализуемая один-в-один».
2. **`RETURN` на L6 корневых страниц** (фазы PROG «к INIT/PROG root», F-PLN, FUEL);
   INIT «L6: RETURN (или self)» — открытое решение.
3. FUEL `Refuel threshold [E]` на L4 слева.
4. DEPART «L2 = Throttle 0/50/100 [A]» одним слотом — циклический пресет, слепое нажатие
   невозможно (три отдельных LSK в базе именно поэтому).
5. Совет «REFRESH перенести в L6-подобный слот» сам нарушает резерв L6.
6. Нет валидаций, пустых состояний, поведения OFFLINE.

### D — button-map: база

Единственный документ, который закрывает все шесть критериев: полные таблицы всех
страниц и фаз, закреплённые слоты между страницами (THROTTLE=R1, SHIP=R2, TARGET=R3,
ALIGN=L2, THR-пресеты L3–L5, SAVE ALL=L5), ветвление ARRIVAL·STN/PLT, slew ↓ как возврат
к активной фазе, 9 разобранных нарушений текущих экранов и 9 замечаний о вскрытых
проблемах (упразднение REFRESH, недостающий SEC DEST, отсутствие команды enter-SC в
транспорте, нет источника DIST TO DROP, выбор корабля → индикация профиля).

**Найденный пробел** (закрыт настоящим merge): «скуп топлива» из фазовой таблицы CRUISE
был сведён к автоматике FSD-ассиста и readout'у топлива — органа фазы не было.

## Вердикт и merge

**База — D (`mcdu-button-map.md`).** Влито из остальных:

| Источник | Идея | Решение |
|---|---|---|
| B | `SCOOP NOW` [A] — явный орган скупа в фазе CRUISE | **Принято**: CRUISE L5; та же команда ядра, что STAR THIS SYSTEM на REFUEL SELECT (осознанное отклонение от «один слот» — замечание 10 базы) |
| A | Класс/scoopable текущей звезды виден в CRUISE | **Принято** в компактной форме: R5 = `FUEL nn.n% · SCOOP/✗` — пара к действию L5 |
| B | Slew ↑/↓ для листания списка F-PLN | **Отклонено**: ←/→ уже листает страницы списка (конвенция `ROUTE n/m →`), а ↓ на PROG занят возвратом к активной фазе — разные оси на разных страницах сломали бы мышечную память |
| B | Явная кнопка Undock в ARRIVAL | **Отклонено**: петля плеча замыкается R6 NEXT PHASE → DEPART (UNDOCK L1), дубль кнопки не нужен (замечание 8 базы) |
| A | HONK выше FSS (L2/L3 местами) | **Отклонено**: honk на прибытии автоматизирован FSD-ассистом, ручной honk реже осознанного FSS — порядок базы сохранён |
| C | Слияние Range + Avg/jump в одну ячейку | **Отклонено**: на FUEL PRED хватает слотов (R3, R4), сжатие ухудшает читаемость без выигрыша |

Итоговая спецификация — обновлённый `mcdu-button-map.md` (правки: CRUISE L5/R5,
состав фазы CRUISE в §2.1, замечание 10).
