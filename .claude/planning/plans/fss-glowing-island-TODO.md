## Инженерные правила из Фазы 2 (обязательны при любых будущих правках `services/`; вывод/история — в ченджлоге)

- **DI-шаблон сервиса:** класс с единственным состоянием `self.ap = ed_ap`; всё остальное через `self.ap.<member>`; инстанс в `ED_AP.__init__`; перенос метода = механическое `self.`→`self.ap.`, логика байт-в-байт.
- **Кросс-сервисные вызовы:** сервис→сервис = `self.ap.<other_service>.<method>`; ED_AP = `self.<service>.<method>`; внешние файлы — через инстанс ED_AP. Wrapper'ов на ED_AP не оставляем; корректность греп-проверяема.
- **Циклический импорт:** сервис НЕ импортирует из `ED_AP` на верхнем уровне: `from __future__ import annotations` + `TYPE_CHECKING`-импорты типов + отложенные импорты рантайм-имён внутри методов.
- **⚠️ Урок:** звёздочные импорты в этой кодовой базе прячут реальные зависимости (см. `ship_rpy_sc_50`-инцидент в ченджлоге) — при переносе/удалении проверять транзитных поставщиков имён.
